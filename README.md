## My Apps

**홈페이지에는 직접 고른 앱만 보입니다.** 가장 쉬운 방법은 홈페이지 'My Apps'의 **앱 선택 (관리자)** 버튼입니다.

- 처음 한 번: [Fine-grained 토큰](https://github.com/settings/personal-access-tokens/new)을 만들어(저장소 Home만, Contents: Read and write) 붙여 넣고 관리자 비밀번호를 정합니다. 토큰은 그 비밀번호로 암호화(PBKDF2 + AES-GCM)되어 그 브라우저에만 저장되며, 소스나 저장소에는 남지 않습니다.
- 다음부터: 비밀번호만 넣고 체크·순서 변경, 앱별 **소개 문구** 입력 → **저장하고 반영**. 1~2분 뒤 반영됩니다.
- 다른 기기·브라우저에서는 토큰을 다시 한 번 등록해야 하고, 토큰이 만료되면 새로 만들어 **토큰 다시 등록**을 누릅니다.

직접 파일을 고쳐도 됩니다. `data/apps-config.json`의 `show` 목록에 저장소 이름을 적으면 적은 순서대로 표시됩니다.
GitHub에서 [apps-config.json 편집](https://github.com/hdlee73/Home/edit/main/data/apps-config.json) → `show`에 이름 추가·삭제 → **Commit changes**를 누르면 1~2분 뒤 반영됩니다.
고를 수 있는 공개 저장소 이름은 `data/apps.json`의 `candidates`에 있습니다.

`앱 목록 갱신` 워크플로가 6시간마다(그리고 설정 파일을 바꿀 때마다) 선택한 앱의 **최신 릴리스**를 읽어 `data/apps.json`에 저장합니다.

- 다운로드 버튼은 릴리스 파일 중 `.apk`, `.exe`, `.msi`, `.dmg`, `.zip` 순으로 대표 파일을 고르며, 같은 종류면 일반 PC용(x64)을 ARM용보다 먼저 고릅니다.
- 소개 문구는 관리자 화면에서 쓴 내용(`overrides`의 `description`)을 쓰고, 비어 있으면 저장소의 About(Description)을 씁니다.

## 자료실 (링크 추가·삭제)

**홈페이지에서 (권장):** 자료실의 **링크 관리 (관리자)** 버튼 → 관리자 비밀번호(앱 선택과 같음) → 주소 붙여 넣기 → **자료실에 추가**.
목록의 휴지통 버튼으로 바로 삭제할 수 있습니다. 1~2분 뒤 반영됩니다.
추가 요청은 `data/link-requests/`에 저장되고, `링크 요청 처리` 워크플로가 제목·요약을 가져와 `data/links.json`에 넣은 뒤 요청 파일을 지웁니다.

**GitHub 이슈로 (보조):**

1. 저장소의 **Issues → New issue → 🔗 링크 추가**를 엽니다.
2. 링크 주소를 붙여 넣고 제출합니다. 여러 개면 한 줄에 하나씩 넣습니다. 제목·요약은 비워 두면 자동으로 가져옵니다.
3. 1~2분 뒤 워크플로가 `data/links.json`에 저장하고, 결과를 댓글로 남긴 뒤 이슈를 닫습니다.

- 유튜브 링크(`youtube.com/watch`, `youtu.be`, `shorts`)는 영상 플레이어가 바로 표시됩니다.
- 분류는 참고자료·유튜브 링크·블로그 링크·기타자료 4가지이며, 기존 링크는 자동으로 여기에 묶입니다. 관리자 화면 `링크 관리 → 세부분류 · 정렬 방식 관리`에서 분류별 세부분류를 추가·이름변경·삭제하고 정렬 방식(최근 추가순/오래된 순/제목순/직접 순서)을 고릅니다. 직접 순서일 때만 목록의 ↑↓로 순서를 바꿀 수 있습니다.
- 구글 드라이브 링크는 구글 화면을 임베드하지 않고, 설명과 **첨부파일 이름 목록**(폴더면 안의 파일, 파일이면 그 파일)을 카드로 보여주며 열기·다운로드 버튼을 붙입니다. 폴더의 파일 목록은 `드라이브 목록 갱신` 워크플로가 6시간마다(그리고 링크를 추가할 때) 새로 읽어 `data/links.json`의 `files`에 저장합니다. 하위 폴더 안의 파일은 보이지 않고 폴더 이름만 보입니다.
- 자료실은 참고자료(드라이브 폴더 이름) → 유튜브 링크 → 블로그 링크 → 기타자료 순서로 분류해서 보여줍니다. 분류는 링크 종류로 정해지며, 추가할 때 고른 분류 이름은 화면 분류에 쓰이지 않습니다. 드라이브에서 **공유 → 링크가 있는 모든 사용자(뷰어)** 로 설정한 링크만 방문자에게 보입니다.
- 블로그·웹 링크는 Open Graph 정보로 제목, 요약, 대표 이미지, 원문 링크 카드를 만듭니다. 네이버 블로그도 지원합니다.
- 삭제는 **🗑️ 링크 삭제** 이슈에 주소를 넣으면 됩니다.
- **저장소 주인(hdlee73)이 연 이슈만** 처리되므로 다른 사람이 이슈를 열어도 홈페이지는 바뀌지 않습니다.

## 게시판

**공지:** 게시판의 **게시판 관리 (관리자)** 버튼 → 관리자 비밀번호 → 제목·내용 입력 → **공지 올리기**. 목록의 휴지통 버튼으로 삭제합니다. `data/notices.json`에 저장되고 1~2분 뒤 반영됩니다.

**방문자 게시판 (로그인 없이 작성):** 서버 없이 구글 설문지로 글을 받고, 응답 시트를 읽어 홈페이지에 보여줍니다.

1. [구글 설문지](https://docs.google.com/forms/create)를 만들고 단답형 **이름**, 장문형 **내용** 질문을 넣습니다. 설정에서 이메일 수집과 로그인 필요는 끕니다.
2. **응답 → 스프레드시트에 연결**로 시트를 만들고, 시트 공유를 **링크가 있는 모든 사용자(뷰어)** 로 바꿉니다.
3. 게시판 관리 화면에 설문지 주소(**보내기 → 링크**, URL 단축 끄기)와 시트 주소를 넣고 **설정 저장**을 누릅니다.

- 글 삭제: 시트에서 그 행을 지우거나 **숨김** 열을 만들어 X를 넣으면 바로 사라집니다.
- 스팸이 걱정되면 **승인한 글만 보이기**를 켜고, 시트에 **공개** 열을 만들어 보일 글에만 O를 넣습니다.
- 응답 시트는 공개 상태라 누구나 볼 수 있으므로, 설문지에 연락처 같은 개인정보 질문은 넣지 않습니다.

## 방문자 수

[구글 애널리틱스](https://analytics.google.com)로 셉니다. 계정·속성을 만들고 **웹 스트림**에 `https://hdlee73.github.io/Home/`를 등록하면 `G-`로 시작하는 **측정 ID**가 나옵니다.
게시판 관리 화면의 **방문자 수** 칸에 측정 ID를 넣고 저장하면 집계가 시작되고, 통계는 구글 애널리틱스 웹·앱의 **보고서**에서 봅니다. 측정 ID는 공개돼도 되는 값입니다.

## 보안

- 관리자 화면의 비밀번호는 서버로 전송되지 않고, 기기에 저장된 암호화 토큰을 푸는 데만 쓰입니다.
- 워크플로는 Actions가 자동 발급하는 `GITHUB_TOKEN`만 사용하며, 저장소에 키나 비밀번호를 넣지 않습니다. 추가 키가 필요해지면 **Settings → Secrets and variables → Actions**에 등록합니다.
- 저장소에 푸시할 수 있는 사람은 저장소 주인뿐이므로 다른 사람이 사이트를 바꿔 배포할 수 없습니다.
